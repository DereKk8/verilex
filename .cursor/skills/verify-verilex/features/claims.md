# Claims

A claim (`.verilex/claims/<claim>.yaml`) is what is true once a word passes, plus the evidence that proves it. `verilex claims` lists each claim as `<claim>@<version>`, where the version comes from a fingerprint of the claim's sentence, args, entry points, preconditions, pinned `requires` and `provides`, and evidence contract. Each word pins one claim version and entry point. A pass is evidence only for the version it ran against, and a chain that holds a word pinned to an older version is refused before launch. A claim's sources anchor it on a sub-feature id and the requirement sentences it maps to, counted only inside the text the id names: the list items, paragraphs and table rows that open with the id in code, and a heading named by it. Each source also pins the sub-feature's other prose (code spans blanked, dated run history left out) by a 12-digit fingerprint. When the id or a mapped sentence is gone or leaves the sub-feature, the sub-feature gains a requirement that no claim maps, or its prose changes, the claim needs review and no admitted word that proves it skips. Another claim's mapping counts only when a curator admitted one of its words for that claim's current version and sources. A re-map keeps the version, but every admitted word that proves the claim is drift-suspect until a curator admits it again over the new sources. The claim's pinned states bind every word that proves it, so a chain that breaks them is refused before launch.

## Sub-features

- `claims-list` lists every claim with its version, sentence, entry points and the words that prove it; `--json` adds the fingerprint, evidence contract and source anchors.
- `claims-stable` keeps the version when only layout changes (line wraps, spacing, key order).
- `claims-version` makes a new version when the sentence or the evidence contract changes, and lists the words still pinned to the old one as stale.
- `claims-stale-refused` refuses a chain that holds a stale word before anything starts, in `run` and `plan`.
- `claims-not-reused` runs a re-pinned word live (`claim changed`) instead of reusing the pass recorded for the old version, and counts no use of the old version toward `propose`.
- `claims-review` flags a claim when a requirement sentence it maps to changes, names the new sentence, makes its admitted words drift-suspect, and asks for nothing when only commands, prose or dated run history change.
- `claims-reviewed` clears the review when the claim is mapped to the new sentence and keeps its version, but keeps every admitted word that proves it drift-suspect (`admitted before claim ...'s sources changed`), so it runs live until a curator admits it again.
- `claims-unmapped` flags a claim when its sub-feature gains a requirement sentence that no claim maps, and names that sentence.
- `claims-scope` flags a claim whose mapped sentence moves to another sub-feature's step, and refuses to clear a review by mapping a sentence outside the sub-feature.
- `claims-prose` flags a claim when its sub-feature's prose changes outside code spans, the words of a Run sentence included, and names the fingerprint to pin after review; a pin makes the next run live.
- `claims-unproven` lets another claim cover a requirement sentence only when a curator admitted one of its words for the claim's current version and sources: a claim without a word, a never-run word, or a word with live uses but no admission covers nothing.
- `claims-uncurated-source` keeps a claim in review when another claim adds a source that maps its unmapped sentence, even after a green live run: the other claim's word was admitted before that source existed.
- `claims-subfeature-gone` flags a claim whose sub-feature id is gone from the feature file, even when the id is still mentioned in prose.
- `claims-pinned-rule` refuses a chain in which a word runs before a state its claim requires, even when the word declares no states of its own.
- `claims-variant` lets a second word prove the same claim and provide its states.
- `claims-binding-refused` refuses a dictionary in which a word names an entry point its claim does not list.
- `claims-requirement-refused` refuses a claim that maps a sentence that is not one requirement sentence, such as dated run history, since it could never match.

## How to get to it (user POV)

- Run `verilex claims [--json]` in a product checkout.
- Edit `.verilex/claims/<claim>.yaml`, a word's `claim:` pin, or the verify skill's feature map, then run `verilex claims`, `verilex check`, `verilex plan` or `verilex run`.

## Gotchas

- The version is the first 12 hex digits of the fingerprint. Copy it from `verilex claims`; it is not a counter.
- Sources are not part of a claim's identity: re-mapping a requirement keeps the version and every pass recorded for it. Change the sentence or evidence contract when the claim's meaning changed.
- A sub-feature is the text its id names: in tally's feature files, the `Sub-features` entry and the step that opens with `` `item-add`: ``. A change to another step's requirement (for example `Expect NAME on its own line.`) flags `item-listed`, not `item-added`.
- A requirement sentence that another claim maps in the same sub-feature is covered there and flags nothing, but only while a curator-admitted word proves that claim at its current version and sources.
- Requirement sentences are not part of the prose fingerprint: each is checked on its own. Editing one gives `requirement changed or gone` and `requirement no claim maps`, not `prose changed`.
- `verilex plan` cuts a long reason to 300 characters with `…`; `verilex check` and `verilex claims` print it whole.
- After a remap, the admitted words that prove the claim are drift-suspect until they are admitted again; restoring `$K` lifts that. Either way the next run is live (`claim sources changed`), so run the chain once before a step that expects `plan: skip 3, run 0`.
- `verilex claims` and `verilex check` exit `0` whatever they report. Read stdout.
- `verilex claims` loads the whole dictionary, so a word contract error (as in **Binding refused**) refuses it too.
- The `sed` commands with `\n` in the replacement need GNU sed.
- Editing a word's `claim:` pin changes its files, so an admitted word becomes drift-suspect until it is proposed and admitted again.
